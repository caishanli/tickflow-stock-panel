# 权威交易日历设计（engine-calendar-authority）

- 日期：2026-09-13
- 状态：待 review（brainstorming architectural 路径产物，实现前需批准）
- 背景事故：2026-09-11 远端（10.126.126.31）`ab_v56fix` 买入 159509，本机未买。根因=引擎交易日历在进程启动时冻结（远端进程 9.10 01:09 启动，日历末端=9.09，连跑 60 小时），9.11 全天 `previous_date`=9.09，MA10 用错窗口（2.8194 vs 正确 2.8215），0.002 边界翻转决策。详见本次 brainstorming 四节结论。

## 1. 目标与非目标

- 目标：
  1. 引擎交易日历改为权威口径（新浪交易日历表），模拟盘（含补跑）与回测统一消费（"全部统一"）。
  2. 日历与进程寿命解耦：进程活再久也不漂移。
  3. 任何降级都不静默：stale 守卫只告警（钉钉+日志，不拦截交易）。
- 非目标：管理页面；多交易所拆分（A 股统一休市，深/北共用上交所口径）；TickFlow 接入（SDK 无此接口）；引入 akshare 依赖（见 §5）。

## 2. 架构与数据流

```
新浪 klc_td_sh.txt（免费，无 key）
  │  stockdata 15:35 收盘 cron 后顺带刷新；引擎启动时文件超 7 天未更新也刷新
  ▼
data/trade_calendar.json {"dates": ["1990-12-19", ...], "fetched_at": "...", "source": "sina"}
  │  _pre_market 每日检查 mtime，变了就 extend（不重启进程）
  ▼
引擎日历（权威口径，进程内只延长不回缩）
  ├── previous_date / get_trade_days / attribute_history（模拟盘+回测统一）
  └── 守卫（三方对账，不一致 → 钉钉+error 日志，只告警）
```

## 3. 组件（4 个独立单元）

1. **抓取解码器**（新文件，如 `backend/app/services/trade_calendar.py`）：拉新浪 txt → 纯 Python 移植解码（akshare `hk_js_decode` 位运算直译，约 60 行，零 JS 运行时）→ 硬编码补 1992-05-04 → 写 JSON（含 `fetched_at`）。可独立测试。
2. **刷新任务**：复用 stockdata 调度（15:35 cron 后顺带，失败不阻塞主流程）；引擎启动时文件超 7 天未更新触发一次。种子文件本次手动生成并随实现提交，冷启动不断粮。
3. **引擎改造**（`backend/app/quant/jqcompat.py` 两处，策略代码零改动）：
   - bundle 初始化优先从文件构建日历；文件缺失才走现有"日期并集"逻辑 + 全局 warn。
   - `_CalendarStore` 新增 `extend(dates)`；`runner._pre_market` 每日比对文件 mtime，变了就 extend。
4. **三方对账守卫**（`runner._pre_market` 内约 20 行）：`引擎末端 vs 文件末端 vs 腾讯探测（上证 000001 最近 40 根最后日期）`，任两方不一致 → `log.error` + 钉钉（补跑期只记 warn 不推，防刷屏）。触发当天在 `sim_logs` 留 `🚨【日历漂移】`污染日标记，供事后对账。

## 4. 三层降级（按优先级）

1. 主：新浪日历文件（权威口径，前后双向可遍历，支持未来日期判断）。
2. 交叉验证/降级：腾讯探测（`ifzq.gtimg.cn/appstock/app/fqkline/get?param=sh000001,day,,,40,qfq`，免费无 key，本机已验证）——文件过期时重建近期锚点；平时每日对账，不一致告警。
3. 兜底：weekday 逻辑（两边都挂才用，只保证不崩）。

## 5. 依赖决策：不引入 akshare

- akshare 强依赖 pandas，打破仓库"主后端零 pandas"边界（ADR-19），且为解码 469 字节引入 7000 行 `__init__` + V8 二进制，代价不对称。
- 自带解码器的失败模式是安全的：新浪改版 → 抓取抛异常/校验不过 → 拒收旧文件 → stale 守卫 paging（"告警而非算错"）。
- akshare 仅作文档级交叉验证参考，不进入依赖树（ precedent：`tencent_minute`/`alt_daily`/`astock_skill` 均为自有小抓取）。

## 6. 错误处理与降级矩阵

| 场景 | 检测 | 行为 |
|---|---|---|
| 新浪抓取失败（网络/被封/改版） | 拉取异常或写入前校验不过 | 拒收，保留旧文件，error 日志 + 钉钉 |
| 文件超 7 天未更新 | 启动/每日检查 `fetched_at` | warn + 钉钉（每周最多一次）；继续用旧文件 |
| 引擎末端 < 文件上一个交易日 | `_pre_market` 三方对账 | error + 钉钉；当天 14:40 照常（只告警），日志标红 |
| 腾讯探测与文件不一致 | 同上对账 | warn + 钉钉，人工看一眼 |
| 文件缺失（全新部署） | 初始化检查 | 回退日期并集 + 全局 warn |
| 写入前校验 | 单调递增；总数 8000~9000；末端距今 ≤400 天；抽查 10.01 休市/1992-05-04 存在 | 任一项不过即拒收 |

原则：永不静默降级（每次 fallback 必有 error/warn 日志，钉钉该推就推）；污染日必留痕。
