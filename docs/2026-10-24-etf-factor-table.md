# ETF 前复权因子表重建（xdxr 事件驱动，2005→今）

## 问题

`data/adj_factor_etf/all.parquet` 原来只有 **2025-06-30 起**的 10 170 行（TickFlow 付费期的
快照）。`sources.apply_qfq_daily` 对因子表起始日之前的日期回填"首因子"，于是 **ETF 更早的
历史复权是常数近似**：实测 510300.SH 2023-06-15 的 `get_price(fq='pre')` 偏高 4.4%。

另外 19 只 ETF 因旧表质量问题被写进 `data/adj_factor_quarantine.txt`，**整段按原始价计算**
（`get_price(fq='pre')` 等于没复权）。

## 试过但不成立的源（别再走这条路）

| 源 | 结论 |
|---|---|
| **baostock `adjustflag=2`（前复权）** | **错的，不能用**。它的 qfq 会在原始价毫无跳空的日期凭空跳变：510880.SH 2009-03-24 原始价 −0.15%、qfq −44%；510300.SH 2012-12-18 原始价 −1.5%、qfq −21%；513530.SH 2025-06-16 原始价 −0.6%、qfq −9.8%。用它反推因子＝把假跳变写进因子表。 |
| TickFlow `ex_factors` | 设计上的权威源，但 **Free 档无权限**（`PermissionError 无除权因子查询权限`），且已有的 2025-06-30+ 快照**漏记真实份额折算**（510150.SH 1:12、159582.SZ 1:5、512600.SH 1:5、159970.SZ 1:6 全被记成 1.0）。 |
| mootdx `xdxr` | ✅ **采用**。覆盖 368 只 ETF（含 2005 年起），事件语义清晰（category 1 分红/送转/配股、11 缩股/份额折算），与真实价格跳空一致。 |

## 做法（`backend/app/quant/etf_factor_build.py`）

1. 逐标的取 xdxr 事件 + **本机 ETF 原始价**（`kline_etf_daily` 已是 raw）；
2. 复用 `mootdx_service._symbol_factor_frame` 算因子（cat 11 → `1/suogu`，
   cat 1 → `(prev_close − 每股红利 + 配股价×配股比例) / (prev_close × (1+送转+配股))`），
   复用 `_merge_cliff_factors` 兜底 xdxr 缺失的份额折算；
3. 把逐日因子压成**事件行**（step function）；
4. **逐个 step 校验**：复权后必须连续 ⇒ 因子变化与价格跳空**必然反向**。
   用"原始价收益 − 当日 ETF 收益中位数"（剔除大盘）在 ±1 日窗口内取同向最大证据，
   要求 ≥ 25% 的**期望跳空幅度** `|s|/(1+|s|)`（1:12 拆分时因子 +1100% 但价格只跌 92%，
   不能拿 |s| 当门槛）；不达标即丢弃该 step；
5. 丢弃 step 后**按保留的事件重算整条序列**（`factor(t) = 1 / Π_{事件日>t} r`），
   保证末值恒为 1.0 —— 直接删行会让其后所有日期残留旧因子（实测造出 24 只末值 ≠1.0）。

```bash
cd backend
uv run --extra dev python -m app.quant.etf_factor_build            # dry-run
uv run --extra dev python -m app.quant.etf_factor_build --apply    # 写盘（自动备份旧表）
```

## 顺带修掉的三个 bug（`mootdx_service`）

1. **`_merge_cliff_factors` 读不到基准因子**：`Timestamp.isoformat()` 带 `T00:00:00`，
   与表里的 `YYYY-MM-DD` 对不上 → 基准因子被当成全 1.0，于是把已经调好的历史价
   **又合成一次悬崖**（重复折算）。改取日期部分。
2. **跨数据空洞的"悬崖"不是份额折算**：512750.SH 缺 2024~2025 两年，
   2023-12-20 → 2026-04-01 被当成 +36.7% 折算。加 `max_gap_days=15` 护栏。
3. **20cm ETF 的涨停日被当成折算**：159971.SZ 2026-06-15 原始价 +20.03%（涨停），
   旧阈值 20% 触发合成 → 造出 1.20 的假因子（正是文档里那句"159971 因子 1.20→1.00 假跌"）。
   ETF 构建改用 30% 阈值（实测 >25% 的价格跳变**全部**有 xdxr 事件背书，无事件的
   都是 20.0% 涨停日）。

## 同时修掉的数据问题

1. **ETF 日线 2016 年之前也是前复权口径**（159943.SZ 差 11.8 倍、159939.SZ 差 2 倍）——
   2026-09-08 那次批量回补把 2005 起的 ETF 历史也写成了 qfq。用 `daily_basis_repair.py
   --etf-repair` 补修 **2 358 个分区 / 9 832 个价格单元格 / 11 只标的**。
2. **隔离名单清理**：`adj_factor_quarantine.txt` 里 19 只 ETF 是旧表冤枉的（按原始价处理
   → `fq='pre'` 等于没复权）。已删除，只保留 3 只股票（301172/603093/688501）。
   备份 `data/.daily_basis_backup/adj_factor_quarantine.before_etf_fix.txt`。

## 已知未修（数据源限制）

- **24 只 ETF/LOF 的日线有 2023-12-20 → 2026-04-01 的空洞**（覆盖率 24%~36%）。
  其中 23 只是 LOF/封闭式基金（169xxx/180xxx/501xxx/506xxx/161226），
  **baostock 完全不覆盖**、TickFlow Free 也无该段数据 → 暂无法补。512750.SH 可补未补。
- `sync_adj_factor`（mootdx 路径）仍被 `_ADJ_FACTOR_QUARANTINED` 禁用；本表由
  `etf_factor_build` 生成，**不会被每日管线覆盖**。若将来恢复 TickFlow 付费额度，
  `kline_sync.sync_adj_factor(asset_type='etf')` 仍会按 (symbol, trade_date) 增量合并进本表
  （`keep="last"`，同锚点口径不冲突）。
